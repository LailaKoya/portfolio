Professional reflection

What this module taught me

A look back at my first year of IT studies, and where I want to take my skills next.

What I've learned

This module pushed me to think beyond just getting code to run, and toward building something a real user could actually rely on. Working on the QuickChat application taught me how much validation logic goes into even a simple registration and login system — checking a username format, enforcing password complexity, and confirming a phone number all required me to think carefully about edge cases, not just the "happy path." Alongside that, my computer networking coursework taught me to think about IT at a systems level: how a client-server model, cabling choice, and IP addressing plan all work together to keep something like a healthcare facility's network secure and reliable. Together, these modules showed me that good IT work is as much about structure and planning as it is about writing code.

My strongest skill right now

I'd say my strongest current skill is problem-solving through logical validation — breaking a requirement down into clear conditions and testing them methodically. When I built the validation rules for QuickChat, I found it satisfying to work through each rule (username formatting, password strength, phone number format) one at a time and confirm each one actually worked before moving to the next. That habit of testing as I go has already made my code more reliable.

A skill I want to improve

I want to get stronger at structuring larger programs cleanly — splitting logic across classes in a way that's easy to follow and easy to extend, rather than figuring out the structure as I go. As my projects grow beyond a single class or two, I know this will matter more.

How I'll develop it

To build this skill, I plan to study how well-structured open-source Java projects on GitHub organise their classes, practise sketching out a program's structure before I start coding, and ask for feedback on my code structure from lecturers and peers rather than only checking that it runs. I'd also like to start writing simple tests for my own code earlier in the process, instead of only validating manually at the end.

How this portfolio supports my future

Having a live portfolio means I don't have to start from zero every time I apply for something — internships, vacation work, or eventually a graduate role. It gives me a place to keep adding projects as I complete them, track my own growth over time, and show potential employers not just what I've built, but how I think about building it. I plan to keep this site updated throughout my degree.
